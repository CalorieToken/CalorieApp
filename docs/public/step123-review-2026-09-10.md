## Repeatable release workflow

1. Start from the current reviewed PR head and list the bounded changes. Preserve the backend/Identity Bridge baseline for a styling-only round.
2. Run changed-feature tests and the Site Style package builder locally. Use the existing CI once the complete batch is ready; address concrete findings rather than repeatedly rebuilding unchanged parts.
3. Build `python tools/build_site_style_release.py --output-dir <release-directory>`. Keep the generated archive, version, SHA-256 and source manifest together.
4. Record one source head and its CI status, then deliver one replacement ZIP. Distinguish source, merged, deployed and human-accepted states.
5. Run one grouped desktop/phone acceptance pass, including logged-in/out and X consent states. Use the administrator inventory to track additional pages instead of silently assuming whole-site coverage.
6. Preserve the Step 1–3 outstanding items when preparing Step 4. Do not mark plans or historical claims as demonstrated features.
