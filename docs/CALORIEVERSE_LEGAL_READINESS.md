# CalorieVerse / CalorieStudio legal-readiness evidence register

Status: engineering evidence register — not a legal opinion or launch clearance  
Last design update: 2026-09-19

This file separates what the repository can currently evidence from what still
requires an external filing, signed instrument or professional review.

### CalorieVerse

CalorieVerse is the current proposed public metaverse name.

Evidence status: **not claimed registered and not declared cleared**.

Required before using a registered symbol or claiming exclusive registered
rights:

1. exact EUIPO/TMview/BOIP search for identical and similar marks;
2. review of the actual goods/services classes needed for software, online
   entertainment/metaverse, creator/platform services and any commercial
   services;
3. opposition/conflict assessment by qualified trade-mark counsel where needed;
4. filing/registration evidence if protection is pursued.

A general web search is not a freedom-to-operate search.

## Copyright and repository code

Current repository boundary:

- original CalorieApp portions created by or lawfully assigned to ICTHendrikse
  are recorded as copyright-controlled material;
- repository visibility does not create a public-domain or open-source grant;
- WordPress plugin components have their own GPL-2.0-or-later declarations;
- contributor rights remain separate unless a written licence/assignment applies;
- Git history is technical provenance, not conclusive legal authorship proof.

Evidence status: **documented rights boundary, but not a universal chain-of-title
certificate for every historical file**.

Open ecosystem direction:

- independent projects may implement public interfaces under their own code and
  branding;
- existing official source is not automatically relicensed;
- protocol/SDK components intended for open licensing need an explicit
  component manifest, provenance review and rights-holder approval first;
- Apache-2.0 is the current software-licence candidate for cleared protocol/SDK
  components, not an active blanket licence.

## Logos, campaign art, 3D assets, audio and generated media

`ASSET_PROVENANCE.md` requires source, permission, licence and attribution
checks before distribution. The repository explicitly does not make a blanket
exclusive-copyright claim for historical CalorieToken logo artwork where the
authorship/assignment chain remains incomplete.

Before CalorieVerse public launch, each shipped asset pack should have an
asset manifest containing:

- asset ID and file digest;
- creator/source;
- creation/commission date;
- written assignment or licence;
- AI-assisted/generated status and human review;
- third-party materials/models/fonts/music;
- attribution requirements;
- permitted commercial/metaverse/marketing uses;
- territory/duration restrictions if any.

Evidence status: **policy exists; full CalorieVerse asset-pack manifest still
required**.

## CalorieStudio user-generated content

Production public uploads are not legally ready merely because the local creator
prototype works.

Before open hosting, publish and implement:

- creator Terms / content licence;
- rights warranty and third-party-content rules;
- notice-and-action / copyright reporting;
- moderation and appeal;
- repeat-abuse/infringement handling where appropriate;
- attribution/provenance rules;
- age/minor safeguards;
- privacy rules;
- commercial-sale/marketplace terms if monetisation is enabled.

Creator copyright should remain with the creator by default; the platform should
receive only the clearly stated rights needed for hosting/display/technical
processing unless a separate commercial licence is agreed.

Evidence status: **architecture defined; production creator terms and workflow
not yet complete**.

## Premium services and revenue

The intended commercial model permits optional premium app/creator features,
managed hosting/API/data services, non-pay-to-win cosmetic/world content and
future reviewed marketplace services.

The revenue model also recognises:

- documented project-cost recovery;
- reasonable founder/developer compensation;
- operating/legal/security reserves;
- a growing ecosystem-treasury allocation;
- a long-term objective for ecosystem infrastructure/community development to
  become a substantial and potentially primary beneficiary of ecosystem surplus.

No percentages are legally or technically activated yet.

Before EU consumer charging is enabled, complete:

- digital-content/service consumer terms and remedies;
- cancellation/withdrawal analysis for the exact product;
- transparent price/renewal/refund flows;
- VAT place-of-supply and OSS/accounting treatment;
- privacy/GDPR review;
- age/minor purchase controls;
- DSA/platform review if hosting or marketplace functions apply;
- chargeback/fraud process.

Evidence status: **commercial architecture approved as direction; exact paid
product terms/accounting still required**.

## Decentralised stewardship

The long-term ecosystem does not have to remain permanently under ICTHendrikse
or the current operator.

A future independent stewardship body may receive specific responsibilities,
revenue, trade-mark rights or licences, but only through deliberate documented
steps. For EU trade marks, an ownership change must be implemented through the
appropriate transfer/recordal process; governance code alone does not change the
registered proprietor.

Possible future vehicle: a Dutch stichting/foundation or another suitable
independent structure. This is a candidate only, not a current legal decision.

Before handover:

- define stewardship charter and protected invariants;
- define which IP/marks are transferred versus licensed;
- sign the relevant assignments/licences;
- complete registry recordals where applicable;
- establish treasury custody, accounting and tax treatment;
- define conflicts, audit, security and succession;
- retain privacy/security rights that governance may not override.

Evidence status: **designed for later transfer; no automatic transfer has
occurred**.

## Current blockers before a commercial public CalorieVerse launch

1. formal CalorieVerse trade-mark clearance/filing decision;
2. final CalorieVerse/CalorieStudio asset-provenance manifest;
3. explicit open-component licence manifest before claiming an open-source SDK;
4. CalorieStudio production Terms/content licence/takedown workflow;
5. premium-service consumer/VAT/accounting terms for the exact offers;
6. DSA review once the actual UGC/platform model is fixed;
7. separate MiCA review before real-token commercial rails;
8. external legal review of the final launch package.

The repository can make these items auditable and fail-closed, but it cannot
replace signed legal instruments, official registers, tax filings or qualified
professional advice.
